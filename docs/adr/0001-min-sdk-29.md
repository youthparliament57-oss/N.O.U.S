# ADR 0001 — Minimum SDK 29 (Android 10)

Date: 2026-07-04
Status: Accepted
Decision Owner: Roshan

## Context

The original README declared `minSdk = 26` (Android 8.0). After review, several modern Android APIs that NOUS relies on are only available on Android 10+:

- **Dark theme** system-wide toggle (Android 10 Q)
- **Scoped storage** enforcement (Android 10 Q, mandatory in 11)
- **Foreground service type** declaration (Android 10 Q)
- **Bubble notifications** (Android 10 Q) — used by overlay HUD
- **BiometricPrompt** unified API (Android 10 Q) — replaces deprecated FingerprintManager
- **AudioPlaybackCaptureConfiguration** (Android 10 Q) — needed for ambient sound classification
- **NetworkRequest** `setSignalStrength` API (Android 10 Q) — used by connectivity module

Android 8.0 (API 26) covers ~97% of active devices; Android 10+ covers ~88% globally (as of July 2026). The ~9% loss is acceptable for the architectural cleanliness gained.

## Decision

Set `minSdk = 29` (Android 10). Compile and target SDK `36` (Android 16, current Play Store requirement).

## Consequences

**Positive:**
- Clean APIs available: `BiometricPrompt`, scoped storage, foreground service types, Bubbles
- Reduced support burden (no Adaptive Icons fallback, no Picture-in-Picture fallbacks)
- Smaller APK (fewer backport libraries)
- Cleaner Compose code (some Compose APIs require API 29+)

**Negative:**
- ~9% device coverage loss globally
- Some legacy devices cannot install (Android 8/9)

**Mitigation:**
- Document requirement clearly on Play Store listing
- Sideload builds can be flagged `minSdk = 26` if a specific legacy device needs support

## Alternatives Considered

- **minSdk = 26**:rejected — too many backport shims needed
- **minSdk = 28**: rejected — minor gain over 29, less clean API surface
- **minSdk = 31**: rejected — loses ~30% of devices, too aggressive for 2026
